# sudoku — 스도쿠 놀이터 🔢

저장소 `arenarun23/sudoku` · 허브 경로 `/sudoku/` · 빌드 없는 정적 앱 (2026-11-18 추가)

## 기능
- 크기 2~16 × 난이도 쉬움/보통/어려움. 초급 2–4, 중급 5–8, 고급 9–12, 최고급 13–16(2026-11-21 추가). 10~16 은 A~G 로 표시(키보드 a~g).
- 상자: 4(2×2) 6(3×2) 8(4×2) 9(3×3) 10(5×2) 12(4×3) 14(7×2) 15(5×3) 16(4×4). 소수(2·3·5·7·11·13)는 상자 없이 가로·세로만(라틴 방진).
- 문제는 매번 난수로 생성: 패턴 해답 → 행·열(띠 안)·숫자 섞기(`crypto.getRandomValues`) → 무작위 순서로 빈칸 만들며 검사.
  - 쉬움 = "하나만 남은 칸"만으로 풀림, 보통 = + "유일한 자리", 어려움 = 유일해만 보장.
  - 생성 속도: 풀이·해 세기는 가로줄·세로줄·상자별 비트마스크(`maskState`/`candOf`). 어려움은 먼저 사람식 풀이로 풀어 보고 풀리면 탐색 생략. 빈칸 만들기 시간 상한 2.5초(넘으면 빈칸이 조금 적은 문제, 그래도 유일해). 측정: 12 이하 0.1초 이내, 16×16 어려움 최대 약 2.9초(브라우저 Worker).
- 힌트 3단계(살펴볼 곳 → 기법 → 정답과 이유, 마지막에 넣기). 틀린 숫자가 있으면 그것부터 알려 줌. 쉬운 기법으로 안 되면 후보가 가장 적은 칸 공개.
- 저장: 입력마다·10초마다·탭 숨김/닫힘 때 자동 저장. 단계를 고르면 "멈춘 곳부터 / 같은 문제 처음부터 / 새 문제" 선택. 학생(프로필)별 기록.
- 게임 방법 화면(`#guide`, 2026-11-20): 약속 3가지(가로·세로·상자) 그림, 4×4 연습판(틀리면 어긴 약속을 알려 줌), 버튼 설명, 꿀팁, 별·저장 안내.
  처음 문제를 시작할 때 한 번 "방법 먼저 볼까요?"를 묻고(`settings.seenGuide`), 게임 중 ❓ 버튼, 주소 `/sudoku/#guide` 로도 연다.
- 대화상자(`ask`)를 연달아 열 때 앞 창의 `close` 이벤트가 늦게 와서 새 창을 취소로 닫던 버그를 고침(2026-11-21): `onclose` 는 창이 실제로 닫혀 있을 때(`!d.open`)만 취소로 본다. 증상: 다 풀고 "다음 단계"를 눌렀는데 그 단계에 풀던 저장이 있으면 아무 일도 안 일어남.
- 해금: 앞 크기 하나 풀면 다음 크기, 같은 크기는 쉬움→보통→어려움. 설정 "모든 단계 열기"(선생님용). 별: 힌트 0 = 3개, ≤2 = 2개.

## 주의
- localStorage 키: `aiedu.sudoku.v1.profiles`, `.current`, `.p.<학생 이름>` (같은 기기·브라우저 안에서만 이어하기).
- 이용 기록: `start`/`finish` + 태그 `<크기>-<난이도>`(예 `9-medium`). 학생 이름·입력 숫자는 보내지 않는다.
- 학생 이름은 `textContent`/`escapeHtml` 로만 화면에 넣는다.
- 시험: 엔진은 Node 로 전 크기×난이도 생성 → 해답 규칙·유일해 검사. 화면은 Playwright 로 시작→힌트→나가기→새로고침→이어하기→완성.

## 화면 배치 — 게임 화면은 기기 화면을 꽉 채운다 (2026-11-20, 레이싱 게임처럼)
- 게임 화면(`#game`)은 `position:fixed; inset:0; height:100dvh` 로 스크롤 없이 화면 전체를 쓴다. 게임 중에는 위쪽 줄(로고·학생 선택)을 숨긴다. 노치·홈바는 `viewport-fit=cover` + `env(safe-area-inset-*)` 로 피한다.
- **크기 자동 대응**: `app.js` 의 `layoutGame()` 이 `visualViewport` 크기·방향을 재서 기준 크기 `--u`(버튼·글자, 10~30px)와 판 크기 `--board` 를 정하고 `#game` 에 `.port`(세로) / `.land`(가로) / `.roomy`(버튼 이름 표시) 를 붙인다. `resize`·`orientationchange`·`visualViewport resize`·`fullscreenchange` 때 다시 계산.
  - 세로: 머리(← 제목 ❓ ⛶) → 판 → 안내 말풍선 → 숫자판(남는 높이) → 도구 → 저장/처음부터/새 문제.
  - 가로: 왼쪽 판(왼쪽 52px 는 허브 아이콘 자리), 오른쪽에 머리·안내(남는 높이)·숫자판·도구·아래 줄. 오른쪽 칸 최소 폭 16u. 칸이 좁아 숫자 버튼이 2.4u 보다 가늘면 숫자판을 3줄로.
  - `layoutGame()` 의 줄 높이(머리 2.8 · 안내 3.9(세로)/3.4~(가로) · 숫자 2.6/2.8 · 도구 3.2 · 아래 2.2 u, 틈 0.45u)와 `style.css` 의 `#game.port/.land` 격자 값은 짝이다. 하나를 바꾸면 둘 다 고친다.
- **전체화면**: 폰·태블릿(`pointer:coarse`)에서 문제를 시작하면 `requestFullscreen` (설정 "게임할 때 전체 화면", 기본 켬). ⛶ 버튼으로 켜고 끈다. 아이폰 사파리는 페이지 전체화면을 지원하지 않아 버튼이 숨고, 보이는 화면을 꽉 채우는 배치만 적용된다.
- 안내 말풍선은 늘 보인다: 힌트가 있으면 힌트(①②③ 단계), 없으면 지금 할 일("빈칸을 누르고 숫자 버튼을 골라요" 등).
- 측정(9×9·12×12·4×4, 3단계 힌트 연 상태, 11가지 크기: 375×667 · 390×844 · 360×780 · 844×390 · 667×375 · 820×1180 · 1180×820 · 1280×620 · 1366×650 · 1920×1000 · 884×1104): 스크롤 0, 화면 밖 0, 영역 겹침 0, 허브 아이콘 겹침 0. 가장 긴 힌트는 낮은 폰 가로에서만 말풍선 안 스크롤.
