# 화면 대응 상세와 테스트

## 왜 이렇게 만들었나
실제 사용 기기는 **삼성 태블릿 가로 화면**(브라우저 주소창·탭 때문에 보이는 세로가 약 560px)이었다. 고정 크기 로고+문구+카드가 합쳐 세로를 넘어 카드가 잘렸다. 그래서 모든 크기를 화면의 **작은 쪽 변**에 비례시키는 방식으로 바꿨다.

## 허브(public/index.html) 구조
- `:root{ --cols:4; --k:1; --u:min(1vw, calc(1.6vh*var(--k))) }`
- 모든 크기는 `clamp(최소px, calc(var(--u)*N), 최대px)` (최소px 는 글자가 너무 작아지지 않게).
- JS `layout()`: `maxCols = (세로화면||폭≤720)? 2 : 4`, `rows=ceil(n/maxCols)`, `cols=ceil(n/rows)`, `k=[1,1,.68,.5,.42][min(rows,4)]` → CSS 변수 설정. `matchMedia` change 로 방향 전환 시 재계산.
- 카드 `li` 너비: `calc((100% - u*2*(cols-1))/cols)`, 최대 270px, flex-wrap + 가운데 정렬 → 5개는 3+2 가 가운데로 정렬.
- 보조 미디어쿼리: ≤460px 높이 → `.desc` 숨김·배지 축소·로고 최소 32px / 세로 폰 ≤700px → `.lead` 숨김·로고 최소 38px / 가로 ≤520px → `.lead` 숨김.

## 측정 기준 (2026-11-03, 카드 4·5개)
태블릿 가로 1280×560·1280×620, 큰 화면 1920×1000, 노트북 1366×650, 태블릿 세로 800×1280, 폰 세로 390×780, 폰 가로 800×360 → 세로 넘침 **0px**. 폰 세로 360×640 만 **4px**(허용). 7개 카드는 작은 폰 세로에서 스크롤 발생(정상 범위).

## 도구
- `scripts/fit-check.mjs`: 위 8개 크기에서 `scrollHeight - innerHeight` 측정, `--shots 폴더` 로 캡처, `--click "#a,#b"` 로 클릭 후 상태 측정(앱 내부 화면 점검용).
- 카드 개수 시뮬레이션: 브라우저에서 `apps.json` 응답을 가로채 항목을 복제하면 된다(playwright `page.route('**/apps.json*', …)`).
- 캡처를 눈으로 확인할 것 — 숫자 0px 이어도 겹침/가림이 있을 수 있다(예: 헤더 버튼을 absolute 로 띄웠다가 '확인' 버튼을 가린 적이 있어 폐기).

## 서비스 앱 쪽 화면 대응 (word 에서 적용한 방식, 다른 앱에 적용할 때 참고)
- `html{font-size:clamp(13px,min(2.95vh,4.9vw),22px)}` 로 rem 전체를 비례, px 고정 크기(마스코트·필기판 높이)를 rem 으로.
- 가로 화면(`orientation:landscape` and `min-width:700px`)은 좌우 2단(`.colA/.colB`, 세로 화면에서는 `display:contents` 로 기존 모양 유지), 홈은 grid-template-areas 로 2단.
- 아주 낮은 화면(≤420px)은 글자 최소 10.5px 까지 축소. 아이용으로 키운 터치 버튼은 세로 폰에서는 유지하고 낮은 화면에서만 줄임.
- 필기판(손글씨)을 연 **세로 폰**은 한 화면에 안 들어간다(허용, 스크롤).
